## 一、概述

[分段控制按钮](/docs/os4/components/navigation/segmented-button)与[标签栏](/docs/os4/components/navigation/tabs)都用于页面内的内容切换，但在信息架构、交互扩展性和视觉层级上承担不同角色。本指南用于明确两者的使用边界，帮助设计与开发在业务场景中做出一致、准确的组件选择。

## 二、组件定义与适用场景

### 2.1、分段控制按钮

分段控制按钮由一个容器和 2–4 个同级选项组成，用于在同一页面内切换互斥的视图维度、统计周期或系统设置模式。

适用于以下场景：

- **选项精简且完全固定**：选项数量严格限制在 2–4 个，后续不会动态增加。
- **视图或统计维度重组**：切换后，下方数据的展示维度或结构发生变化，例如屏幕时间管理中的“每日 / 每周”、用眼时长统计中的“日 / 周 / 月”、应用使用限制中的“名称 / 类别”。
- **并列的设置或任务模式切换**：用于两个或多个对等功能模块之间切换，例如声音与触感中的“声音 / 触感”、触感反馈中的“清脆 / 低沉 / 弹柔”、自动任务中的“任务中心 / 我的任务”。
- **需要视觉降噪**：当页面下方包含高密度统计图表、触感示意图或多彩应用图标列表时，使用无彩色的分段控制按钮，以保持页面视觉平衡。

### 2.2、标签栏

标签栏由一组独立标签组成，宽度可随文本自适应，用于对同一列表或内容集合进行多维度的属性筛选与分类浏览，并支持横向滚动和动态扩展。

适用于以下场景：

- **选项较多或需要动态扩展**：选项数量较多，或会随时间、用户操作持续增加，例如相册旅途中的年份归档、笔记中的自定义文件夹分类。
- **包含“全部”集合的子集筛选**：第一个选项通常为“全部”或“通用”，其余选项用于筛选特定属性的内容，切换后列表结构保持不变，例如“全部 / DOC / XLS / PDF / PPT”或“全部 / 位置 / 相机 / 麦克风”。
- **需要品牌色强化或附加入口**：需要通过系统或应用主题色强化当前选中状态，或在标签栏一侧固定文件夹管理等功能入口。

## 四、选择方法

组件选择分两步判断。

### 4.1、判断切换对象

- **切换内容分类**：第一个选项通常为“全部”“推荐”或其他总类，其余选项按属性或条件从同一数据集中提取子集。无论选项数量多少，都应使用标签栏。
- **切换视图或模式**：选项用于切换同一内容的视图、模式或统计周期，且选项彼此平级、互斥。此类场景继续判断选项数量与扩展性。

### 4.2、判断数量与扩展性

- 选项固定为 2–4 个，且可在当前容器内完整展示时，应使用分段控制按钮。
- 选项超过 4 个、可能动态增加或无法完整展示时，应使用标签栏，必要时支持横向滑动。

## 五、设计规范与避坑指南

### 5.1、应

- **控制文案长度**：分段控制按钮的选项文案应简短、对等，建议使用 2–4 个汉字，例如“每日 / 每周”“清脆 / 低沉 / 弹柔”，保证选项布局均衡。
- **保持筛选结构一致**：使用标签栏时，切换不同标签应只刷新下方列表的数据内容，卡片样式与排版结构应保持一致。
- **根据搜索对象选择组件**：两者都可置于搜索框下方。用于改变搜索结果的视图或模式时，使用分段控制按钮；用于按文件夹或内容属性快速筛选时，使用标签栏。

### 5.2、不应

- **不应超载分段控制按钮**：选项不得超过 4 个，避免触控热区过窄或多语言文案截断。
- **不应混用视觉样式**：不应将分段控制按钮的选中区域改为高饱和度彩色，也不应将标签栏强制拉宽为等分屏幕的分段样式。
- **不应在分段控制按钮中加入“全部”**：分段控制按钮用于互斥的平行维度；业务需要“全部”汇总视图时，应改用标签栏。
