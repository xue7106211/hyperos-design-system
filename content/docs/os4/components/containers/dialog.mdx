# 弹窗 Dialog

## **一、概述**

弹窗（Dialog）是一种模态容器，用于承载用户当前必须关注的信息或需要立即完成的操作。弹窗出现后，用户暂时无法操作背景界面，完成操作或关闭弹窗后方可返回原界面。

弹窗具有较强的打断性，仅适用于重要提示、操作确认、信息选择或内容输入等场景。普通状态反馈或低优先级信息应优先使用轻提示、横幅通知等非模态组件。



## **二、原则**

- **必要性**：仅在信息必须立即处理或操作需要明确确认时使用，避免频繁打断用户。（再看下）

- **简洁性**：仅保留完成当前任务所必需的信息和操作，避免在弹窗中承载复杂、冗长的流程。



## **三、类型与结构**

### **1\. 类型**

#### **1\.1 信息通知弹窗**

用于展示错误、说明、状态提示等用户必须关注或主动查看的信息。内容应说明当前状态，并尽可能提供解决问题的操作入口。

![5\.png](/media/os4/components/containers/dialog/5.png)



#### **1\.2 操作确认弹窗**

用于用户执行操作前核对信息并确认是否继续，适用于提交、保存、退出、状态变更或高风险操作。高风险场景应明确说明可能产生的影响和后果。

![7\.png](/media/os4/components/containers/dialog/7.png)



#### **1\.3 选择弹窗**

用于通过列表或选择器提供一项或多项选择。单选和多选均需要使用按钮进行确认，

> 如果是高频轻量的单选操作，建议使用 Actionsheet 组件
>
>

![8\.png](/media/os4/components/containers/dialog/8.png)



#### **1\.4 输入弹窗**

用于用户完成名称、密码、验证码或其他简短内容的输入。输入内容为空时，确认按钮应保持禁用，若输入内容不符合要求，应提供必要的错误说明。

![9\.png](/media/os4/components/containers/dialog/9.png)



### **2\. 结构**

弹窗由标题区、内容区和按钮操作区组成。

![10\.png](/media/os4/components/containers/dialog/10.png)

- **标题区**：用于概括弹窗目的，弹窗的必选区域，不可省略

- **内容区**：可承载文本、列表、输入框、选项、图标、图片或其他必要内容。

- **按钮操作区**：用于承载确认、取消或其他操作。应为用户提供明确的完成或退出（取消）路径。



## **四、交互状态**

### **1\. 弹出与聚焦**

弹窗打开后应显示在当前屏幕、窗口或分栏内容区域的视觉中心，并通过全屏蒙层与背景内容建立明确层级。用户的操作焦点应进入弹窗，背景界面不可响应点击或滑动。

同一任务流程中应避免叠加多个弹窗。如需展示后续信息，应关闭或替换当前弹窗，避免形成多层级阻塞。

![12\.png](/media/os4/components/containers/dialog/12.png)

![23\.png](/media/os4/components/containers/dialog/23.png)



### **2\. 按钮状态**

详细按钮规范，可参考文档 [按钮 Button /  组件规范文档](https://mi.feishu.cn/wiki/Y1cowhz0FiMGHFknKpZcd7cYnUp)

- **Enabled**：按钮可操作，点击后执行对应操作。

- **Hover（条件支持）**：鼠标、触控板等指针悬停时的状态，移动端不强制支持

- **Pressed**：用户按下按钮时提供即时状态反馈。

- **Disabled**：当前条件不满足时按钮不可操作，并与可用状态形成明确区分。



### **3\. 关闭规则**

点击取消按钮、返回操作或完成当前任务后，弹窗关闭并返回原界面。

弹窗默认支持点击蒙层或返回关闭；操作必须处理的弹窗时，需关闭【点击蒙层关闭】的快捷交互，应优先通过明确按钮关闭，避免误触导致内容丢失或跳过必要操作。

手势可以返回，补充什么特殊情况下会强阻断

![13\.png](/media/os4/components/containers/dialog/13.png)



### **4\. 输入与键盘**

输入弹窗唤起键盘后，应根据剩余空间调整位置或可视高度，避免输入框、错误提示和操作按钮被键盘遮挡。内容超出可用区域时，应优先滚动内容区，并保持关键操作可见。

![16\.png](/media/os4/components/containers/dialog/16.png)

### **3\. 按钮规格**

同一弹窗仅设置一个主要操作。破坏性操作应使用危险样式，并在内容区明确说明操作对象、影响范围和不可逆结果。按钮的其他规则参见 [按钮 Button / 组件规范文档](https://mi.feishu.cn/wiki/Y1cowhz0FiMGHFknKpZcd7cYnUp)。

- **一个按钮**：用于仅需用户知晓、无需决策的信息，按钮承担关闭弹窗的作用。

- **两个按钮**：默认横向排列，主要操作位于右侧，取消或次要操作位于左侧。受多语言或大字体影响无法完整展示时，切换为纵向排列

- **三个及以上按钮**：默认纵向排列；主要操作位于顶部，其余操作依次向下排列。受多语言或大字体影响无法完整展示时，依然纵向排列（OS5预期支持双行按钮扩展）。

![image\.png](/media/os4/components/containers/dialog/image.png)



### **4\. 视觉效果**

组件提供高级材质样式，通过系统设置，开启【高级材质】后，弹窗会在应用页面带来更通透和谐的视觉体验。

![20\.png](/media/os4/components/containers/dialog/20.png)

- **纯色样式：**纯色背景色 `miuix_color_bg_compoment`

- **轻透磨砂：**开启后容器会呈现模糊混色\+高光边的透色效果，参数如下

    - 模糊：`Blur_L`

    - 混色：`Pured_Regular_Glass_Light`

    - 描边：`Glass_Stroke_Middle_Light`

    - 阴影：`Shadow_Regular`



## **六、多端设计指南**

手机、折叠屏与平板采用一致的弹窗结构、交互方式和视觉规则，并根据当前屏幕或窗口可用空间进行响应式适配。

### **1\. 手机**

弹窗在屏幕可用区域内居底显示，宽度由屏幕宽度减去两侧页面边距计算，最大不超过380dp。横屏或分屏场景下，应基于当前窗口而非完整屏幕计算弹窗尺寸。

#### 手机竖屏

- 弹窗最大高度为整机屏幕的70%

- 左右间距稳定12dp，距离底部安全区12dp

![14\.png](/media/os4/components/containers/dialog/14.png)

#### 手机横屏

- 弹窗最大高度为整机屏幕所有可用区域（排除状态栏\+导航条\+安全边距）

- 垂直居中显示，距离底部安全区12dp

![15\.png](/media/os4/components/containers/dialog/15.png)



### **2\. 折叠屏**

折叠屏外屏与内屏使用同样的适配规范，因此整体与手机端规范一致

### **5\. 避让规则**

弹窗应避让状态栏、导航栏、屏幕圆角、挖孔、系统手势区域、折叠区域及软键盘。空间不足时，应优先调整弹窗位置或可视高度，并通过内容区滚动保证信息和关键操作完整可见。



## **七、多语言与大字体**

### **1\. 多语言**

弹窗应支持不同语言下的文本长度变化，不得通过缩小字号容纳长文本。标题和正文可根据内容自然换行，关键提示和高风险操作不得使用省略号隐藏核心语义。

按钮文案无法完整横向展示时，应优先增加按钮宽度或切换为纵向排列，避免文字裁切、按钮重叠或弹窗超出屏幕可用区域。详见 按钮规范

### **2\. 大字体**

弹窗文字应跟随系统字号规范缩放，容器高度和内容布局随文字大小自适应。文字放大后不得出现裁切、重叠、遮挡或操作按钮不可见等问题。

达到最大高度后，仅内容区滚动；标题区和按钮操作区应尽可能保持可见。触控区域不得因字号或布局变化而缩小。

- **大字缩放比例**

||字号|100%|145%|200%|
|---|---|---|---|---|
|标题|18|18|23\.4|30|
|正文|16|16|21\.8|28|
|备注|13|13|18\.8|25|

## **八、动效**

弹窗出现时，蒙层与容器应通过淡入和轻微缩放建立层级；关闭时采用对应的反向动效。动效应简洁、快速，不得延迟用户操作。

系统开启“减少动态效果”后，应弱化或取消缩放，仅保留必要的透明度变化，确保信息层级清晰。
